## Game rules
- 2026-10-27: Theme-agnostic: actions, responses, outcome matrix, Damage table and authored counters are data (configs/definition.json). 6 actions, 6 responses. Payoff U(r,a) = +D(r,a) on a win, -D(r,a) on a loss, 0 on a draw (ADR 0010). Example table: circulant f = [0, +3, +1, 0, -1, -3], so each action has a Heavy counter (3) and a Light counter (1); the authored counter is the Heavy counter.
- 2026-10-27: Balance check at load, two parts. (b) Every row and column of U sums to 0: this alone gives sigma* = uniform and v* = 0 with no LP; a unit test checks uniform scores exactly 0 against every column. (a) Every row and column has exactly 2 wins, 2 draws and 2 losses: not needed for Nash, but Win-stay/lose-shift, level-k, mirror and the population prior rely on every action having exactly two counters. An LP comes back, with an ADR, only if an unbalanced theme needs it.
- 2026-10-27: The Opponent commits its response before it reads the player's action.
- 2026-10-27: Match ends at HP 0 or a 120-exchange cap; a lost exchange costs the loser D(r,a) HP; start HP about 60, tuned on dev seeds.
- 2026-10-27: Big hit (ADR 0011): three consecutive exchanges in which the same side takes damage every time, totalling >= 7 (window 3 and threshold 7 are game data). Flagged on the completing exchange; Outcome stays win/draw/loss. Scan left to right, windows never overlap and never cross a match boundary. Exchange 1 of a match has the Match-start context. About 4.2 per side per 300-exchange session under uniform play.
- 2026-10-27: No saved profiles, no leaderboard, no storage interface. Memory lasts for one session (3 matches), in memory only. The corrupt-profile rule in CLAUDE.md stays, dormant.
- 2026-10-27: Prediction is history-only; no state snapshot (ADR 0003 deferred).

## Seeds and randomness
- 2026-10-27: The harness uses the fixed seeds in configs/ and seeds/. The shipped game draws a fresh session seed at session start (from a secure source in the Game layer), passes it to the core and writes it in the play log header, so every real session is different yet reproducible from its log.
- 2026-10-27: Each archetype and the Opponent draw from separate Rng streams derived from the session seed, so Random is independent of the Opponent's draws.

## Archetypes and harness
- 2026-10-27: Seven archetypes, built before the Opponent: Spammer, Cycler, Win-stay/lose-shift, Out-guesser, Random (negative control), Big-hit repeater, Burned avoider. Scripted Level-1 and Mirror-1 players exist only for the level-k/mirror keep rule.
- 2026-10-27: Big-hit repeater: plays uniformly at random, except when the previous action equals the a0 of a big hit it landed earlier and >= 30 exchanges have passed since it last used that entry; then it replays that Big-hit sequence (a1, a2, a3).
- 2026-10-27: Burned avoider: spams one action with 40% uniform noise. In a start context where it took a big hit it avoids that Opening with probability 0.5^(dt/100), dt = exchanges since the burn; on a broad match (previous action only) with half that. Avoiding redraws uniformly from the other five actions.
- 2026-10-27: Win-stay/lose-shift: a win repeats the action; a draw or loss shifts to one of the two actions that beat the Opponent's last response (seeded Rng picks). Its oracle ceiling is logged next to its prediction accuracy.
- 2026-10-27: Out-guesser: faded counts (0.9 per exchange) of the Opponent's responses, predicts the most likely response, plays one of the two actions that beat it, 70/30 with a per-seed preference between the heavy and light one (drawn at random, logged), plus 10% uniform noise. Its oracle ceiling (about 0.65) is logged.
- 2026-10-27: Heldout set = 20 seeds. Pass criteria apply to the mean across seeds; per-seed rows are logged. Harness sessions are fixed-length: 3 matches of 100 exchanges, and HP does not end a match in the harness. Early = exchanges 1-50, late = 201-300. A separate game-rules run reports real session lengths and win rates.
- 2026-10-27: Pass: late prediction accuracy >= chance + 0.20 for Spammer, Cycler and Win-stay/lose-shift. Random: mean prediction accuracy in 1/6 +/- 0.05, the evidence gate never opens on any seed (so no Insights and no Recalls), and lambda = 0 on every exchange; its mean payoff within v* +/- 0.15 (0.05 x max damage) is kept as a simulator check, not an AI check. Big-hit repeater: on replay exchanges pooled over seeds (>= 100 per position), the mixed forecast's top-prediction accuracy >= chance + 0.20, reported for the Opening and each Follow-up, with the expert's own accuracy logged beside it; the bar is checked on dev first. Burned avoider: on exchanges in burned contexts (>= 100 pooled), the full config's log-loss beats the config without the Avoidance expert by more than t x paired SE.
- 2026-10-27: Habit-switch unit test: a sequence switches from spamming action 1 to spamming action 4; recovered = top prediction is action 4 for 5 exchanges in a row, within 30 exchanges of the switch. Fading tuning on dev must keep it passing, at w = 0 and at the tuned population-prior strength w.
- 2026-10-27: All tuning (start HP, gate threshold, Insight limits, fading, alpha, k0, s, beta_avoid) is on dev seeds. Fixed, not tuned: big-hit window and threshold, the 1/2 broad ratio, 0.7 per miss, pool size 16, the 30-exchange repeater gap, prior shrinkage 20. The gate threshold is fixed with Random on >= 100 dev seeds after the final expert set is chosen, before any heldout run, and never changed after seeing heldout results.
- 2026-10-27: One heldout run at the end reports v1, freq and v2 (whatever survived the ablations) together.

## Opponent v1
- 2026-10-27: Experts: order 0, order 1, order 2 and (previous action, previous response), each a table of counts with a symmetric Dirichlet prior. A freq config (order 0 alone) runs beside the full config on the same seeds (ADR 0004).
- 2026-10-27: Fading is per visit: a context's counts fade by gamma (start 0.98) once each time that context is visited. Order 0 is visited every exchange. Global-time fading is one dev ablation row.
- 2026-10-27: Experts are mixed by Fixed Share (alpha start 0.01): w_i <- w_i p_i(a) for awake experts only, renormalised so the awake experts keep their total weight; then w_i <- (1 - alpha) w_i + alpha / K over all K experts, asleep or awake. An expert that Abstains keeps its weight (sleeping experts).
- 2026-10-27: At match start: counts x 0.5; expert weights become 0.5*w + 0.5*(1/K); Big-hit memory and the Avoidance record carry over unchanged.
- 2026-10-27: Evidence gate: one test on the mixed forecast's cumulative log-likelihood ratio vs uniform over the session, starting threshold ln(1000). It latches open for the rest of the session. No hedged gate.
- 2026-10-27: An Insight needs the gate open, top probability >= 0.4 and >= 5 observed faded counts in its context (both tuned on dev). Dirichlet and population-prior pseudo-counts never count toward the 5.
- 2026-10-27: Response selection: while the gate is closed, play sigma* (uniform). Once open, Thompson Sampling: pick an expert with probability equal to its weight, draw a forecast from its posterior, play the best response to it. Test mode uses the mixture mean. Thompson Sampling draws only among awake experts. Ties between responses go to the authored counter, then the lower index; ties between predicted actions go to the lower index.

## Opponent v2 (ADR 0007, spec .scratch/opponent-v2/spec.md)
- 2026-10-27: Thompson Sampling covers every v2 expert, so predictor ablation rows all run with the same selector: CTW draws a depth on the current path with the beta weights, then samples that node's KT (Dirichlet 1/2) posterior; longest-match samples its Dirichlet(1/2) posterior; level-k and mirror apply their fixed transform to a sample of their base forecast. Only the +safe exploitation row changes the selector.
- 2026-10-27: Match start, for everything: counts (v1 tables and CTW nodes, all three trees) x 0.5; CTW beta log-odds x 0.5 toward 0; Fixed Share weights 0.5*w + 0.5/K; population-prior pseudo-counts are stored apart (so Insights can exclude them) but fade and halve exactly like observed counts, so the prior washes out as this player's evidence grows; the longest-match history, Big-hit memory, the Avoidance record, the evidence gate score and the safe-exploitation budget k carry over unchanged.
- 2026-10-27: Node pool: up to 400 exchanges x depth 6 x 3 trees (action-first, response-first, and the mirror CTW over the Opponent's own responses), about 7.2k nodes, preallocated.
- 2026-10-27: v2 components are added one at a time after v1 and kept only if they earn their place on paired dev seeds.
- 2026-10-27: CTW runs as two experts: action-first context a(t-1), r(t-1), ... and response-first r(t-1), a(t-1), ..., depth 6. v1's order-1 expert stays in the mix as a hedge.
- 2026-10-27: CTW nodes store log Pw and the log product of the children's Pw, updated by one factor when the path child changes. Each node's beta log-odds fades by gamma and is clamped to [-6, 6]; unit test: 50 symbols favouring the node, then 50 favouring the child, beta crosses 0.5 within 15 symbols of the flip.
- 2026-10-27: Selector: while the gate is closed, play sigma*; once open, play lambda*BR + (1-lambda)*sigma* on the mean mixed forecast. lambda = clamp(k / (v* - min_a U(BR, a)), 0, 1), which is min(k/3, 1) for the example table. Budget k (damage units) starts at k0 = 0.75 (tuned on dev in [0.3, 3]) and grows by expected gifts, sum_r sigma_t(r) U(r, a_t) - v*. ADR 0006 is superseded only if this ablation wins.
- 2026-10-27: Comparisons use paired seeds with the SE of the paired difference reported. Margin = max(0.02, t x paired SE) for accuracy and log-loss, max(0.06, t x paired SE) for payoff, where t is the two-sided 95% Student-t critical value for (seeds - 1) degrees of freedom (2.09 for 20 seeds). Strict wins (Win-stay/lose-shift win rate, Out-guesser payoff) must exceed v1 by more than t x paired SE.
- 2026-10-27: Ablation rows (dev only, one log.csv row each, greedy in this order): v1, v1 without Fixed Share (alpha = 0, a plain Bayesian mix), +CTW x2, +longest-match, +level-k/mirror, +safe exploitation, optional +CTW at 3 gammas, global-time fading, then (ADR 0011, against the best surviving config) +Big-hit sequence expert (exact only), +broad matches for it, +Avoidance expert (exact only), +broad matches for it. Every row runs on all seven archetypes. A row beats the row above if it improves at least one archetype by more than t x paired SE and is not worse on any by more than the margin. Predictor rows are judged on prediction accuracy, selector rows on payoff.
- 2026-10-27: Level-k/mirror experts have their own keep rule: (a) not worse on Spammer, Cycler, Win-stay/lose-shift and Random by more than the margin in prediction accuracy, (b) >= 0.3 higher accuracy than without them on the scripted level-1 and mirror-1 players, (c) not worse against Out-guesser by more than the margin, on payoff.

## Big hits (ADR 0011)
- 2026-10-27: Big-hit memory: a preallocated pool of 16 entries for big hits the player lands on the Opponent (start context, Big-hit sequence, m_exact = m_broad = 1). Same start context and sequence: reset strengths to 1. Full pool: replace the lowest max(m_exact, m_broad), oldest first.
- 2026-10-27: Big-hit sequence expert: fires on the Opening on an exact match (start context) or a broad match (a0 only; exact takes precedence), then on each Follow-up while the player follows; the first wrong prediction stops the chain. Forecast: Dirichlet 0.5 plus s x m_exact (or s/2 x m_broad) on the predicted action, s tuned on dev in [0, 5]. A miss multiplies the chain's strength by 0.7, a hit resets it to 1; an entry is deleted when both strengths are below 0.1 (7 misses in a row each). It Abstains when nothing matches.
- 2026-10-27: Recall: a Commentary line from a Big-hit memory entry. It needs the gate open, the expert firing, and its predicted action as top prediction with p >= 0.4; when it stops follows from that cutoff (after 3 exact or 1 broad miss).
- 2026-10-27: Avoidance expert: a pool of 16 entries for big hits the Opponent lands on the player (start context, Opening a1). While firing, p(a1) proportional to exp(-beta_avoid x m), others equal, eps = 0.05; beta_avoid tuned on dev in [0, 3]. Playing a1 there anyway multiplies m by 0.7; avoiding leaves it unchanged (no reset). It Abstains when nothing matches.

## Unity screen
- 2026-10-27: The Belief is shown from the first exchange, labelled as a guess while the evidence gate is closed. Only Commentary waits for the gate. A demo config (for example a lower gate threshold) is allowed only if it passes the same harness, is logged as its own config and is labelled on screen.
- 2026-10-27: No timer per exchange. One exchange per key-down; the next needs a key-up first, plus a 0.4 s lockout during the reveal.
- 2026-10-27: Commitment: the Game layer (not Core) hashes "response|nonce" with SHA-256, where the nonce is 16 bytes from System.Security.Cryptography.RandomNumberGenerator (unseeded, so it cannot be predicted; the Opponent's seeded stream is untouched). The screen shows the first 16 hex chars while locked in and the nonce after the reveal; the full hash and nonce go in the play log so anyone can verify.
- 2026-10-27: Manual play log: the Game layer writes one timestamped CSV per session to Application.persistentDataPath. Header: schema version, config file name, seed, AI version (v1/v2). Rows per exchange: session, match and exchange index, action, response, outcome, damage, big-hit flag, predicted top action, forecast probability of the actual action, leading expert, gate open, lambda, reaction time ms (data only, never used by the AI). Rows are buffered and written at match end and on quit; all file I/O is in try/catch, and a failure shows one on-screen warning while play continues. The AI never reads these files; they never go in the repo; docs/playtest.md explains how to copy one out.

## Human data
- 2026-10-27: The headline human result is fixed before any data: prediction accuracy over exchanges 31 onward, against chance (1/6). The slide shows the full learning curve with exchange 30 marked.
- 2026-10-27: An analyze-human command in Core.Sim (pure C#, no Unity) reads a folder of play logs and reports: the learning curve with confidence bands, accuracy from exchange 31, log-loss vs uniform (bits per exchange), how often the gate opened, and a per-player table. Each run appends one row to experiments/log.csv.
- 2026-10-27: Confidence intervals come from a bootstrap over players, not exchanges, and the player count is always reported. No human result is reported with fewer than 8 different players.
- 2026-10-27: Teammates' sessions are dev data and may inform tuning. Fresh players (interviewers, friends) are the report set and are never used for tuning.

## Population prior (ADR 0008)
- 2026-10-27: CLAUDE.md allows a pretrained table if it ships as a bundled config and passes ADR 0008's rule; network calls stay banned.
- 2026-10-27: Population prior: a relational table (next action's relation to the last action and the Opponent's last response, per last outcome), learned from teammates' play logs only, shipped as configs/prior.json, applied as w pseudo-counts (tuned on dev in [0, 20]) to the order-1 and (action, response) experts and, if v2 ships, CTW depth-1/2 nodes. Buckets per last exchange: big hit on the player, win, draw, loss, big hit on the Opponent; each big-hit bucket shrinks toward its plain bucket (on the player toward win, on the Opponent toward loss) as (counts + 20 x parent) / (n + 20). The ship decision uses teammates' logs only (leave-one-player-out, early accuracy on exchanges 1-30, no archetype worse than the margin, Random never opens the gate); the fresh players' report set is used once, to report, never to decide.
